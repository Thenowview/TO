- Implement the connected objective → demand → business case → prioritization → capacity/budget → scenarios → approval → delivery/change → benefits/rebalancing workflow with acceptance evidence.
- Existing dated audits, release logs and design documents are historical evidence. Their PASS/BLOCKED labels do not describe today's deployment or override the current owner requirements.

## Cleanup boundaries

This preparatory cleanup removes only demonstrably unused imports and exact redundant evidence copies. Preserve source, tests, migration ledgers, fixtures, locale catalogs, compatibility routes and signing/encryption identifiers. Lack of a direct import is not proof that a route, command, asset or reflection-discovered module is unused.

Production merge, deployment and public installer distribution require the separately reviewed release decision. Review the master execution prompt and requirement ledger for the full acceptance scope; no customer-readiness claim is made here.
